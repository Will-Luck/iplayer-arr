## Reply text

Both fixes are out in v1.1.8.

The **size estimate** during download was a fixed-bitrate calculation against the *requested* quality, so when BBC silently delivered a lower variant the denominator was wrong (your ~1GB / actual ~350MB). The active row now just shows bytes-downloaded plus a "Determining quality…" placeholder. The truthful values land once the download finishes and ffprobe has confirmed the encoded height.

The **filename quality** was set from what we asked for, not what BBC actually sent. The worker now ffprobes the completed file and renames the directory and .mp4 to match the real height (so e.g. a 1080p request that BBC delivers as 540p ends up as `…540p.WEB-DL…` on disk). The history row also shows the real quality. The truncation gate has been moved to use the actual quality threshold, which fixes a class of false positives where legitimate lower-quality downloads were being rejected for "looking too small for 1080p".

Pull and give Catherine Tate (or whatever else was misbehaving) another try when you get a chance — should land at the right size and filename now.
